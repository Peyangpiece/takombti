## 0. この文書について

### 0.1 目的

本人ではなく**友達が本人について答える**アンケート（他己診断）を集め、指定した人数が答え終わった時点で、
4 つの軸による 16 タイプのどれに見られているかを判定し、詳しく面白い分析文を表示するウェブアプリを作る。
この文書は、作る人がこれだけを読めば迷わず実装・テストできることを目標にする。

### 0.2 用語

| 用語          | 意味                                                               |
| ------------- | ------------------------------------------------------------------ |
| ホスト        | 診断を作り、自分について友達に答えてもらう人                       |
| 回答者        | ホストに頼まれて、ホストについて答える友達                         |
| 診断          | ホストが 1 回作る 1 件のアンケート。人数・回答・結果をまとめたもの |
| 目標人数（N） | ホストが作るときに決める回答者の人数                               |
| 軸            | 性格を分ける 4 つの物差し（後述）                                  |
| 極            | 軸の両端（例：外向と内向）                                         |
| 自己回答      | ホストが自分で同じ質問に答えたもの（任意）                         |

### 0.3 前提と、そう決めた理由

### 0.4 他己診断で測れること・測れないこと（設計の根拠）

性格心理学の研究では、他人による評定は本人の評定と同じくらい性格をよく言い当てることがあり、
特に**外から見えやすい特性（人と話す量など）ほど本人と他人の評価がよく一致する**ことが知られている
（Funder の「現実的正確さモデル」、Vazire の「自己と他者の知識の非対称性（SOKA）モデル」など）。
逆に、心の中の不安など見えにくいものは他人には当てにくい。

このため本アプリでは次の方針を取る。

- 質問はすべて**友達が実際に見聞きできる行動**で書く（「〜と感じている」ではなく「〜している」）
- 判定結果は「あなたの本当の性格」ではなく「**周りからこう見えている**」と表現する
- 自己回答があれば、自分の見方とのずれを「ギャップ」として示す（ジョハリの窓の「自分は知らないが他人は知っている自分」に当たる部分で、他己診断ならではの面白さになる）

### 0.5 名前

- 名前：**たこ診**（たこしん）。表記はひらがなの「たこ」＋漢字の「診」で固定する
- 副題：**友達が答える16タイプ診断**。「他己（たこ）」の読みに気づかない人もいるため、トップ・シェア画像・リンクの見出し（OGP）では名前と必ずセットで出す
- 由来：「他己（たこ）診断」の略
- 看板のキャラクター：タコ（自前で描く）。界隈の色に合わせた 4 色の姿を用意し、結果画面とシェア画像に出す
- 公開前に、商標（特許庁の J-PlatPat）、アプリストア、ドメインで同じ・似た名前がないかを調べる（§13 C1）

ほかの候補だったもの（ウワサの16・みられ16・トモタイプ・ヒトミル）は使わない。

## 1. 全体の流れ

```
ホスト                          回答者（N 人）
───────                        ─────────
① 名前と人数 N を入れて作る
② （任意）自分でも答える
③ 招待リンクを LINE などで送る ──→ ④ リンクを開く
                                  ⑤ 16〜32 問に答える（約 3 分）
⑥ 回答状況を見る（○/N 人）  ←── ⑤ を N 人が終える
   ※ N 人そろうまで結果は一切見えない
⑦ N 人目が答えた瞬間に結果が確定
⑧ 結果発表 → 詳しい分析 → シェア
```

要点：**結果は N 人目の回答が保存された時点で 1 回だけ計算し、以後は変えない**。
それより前は、途中の傾向も含めて、サーバーの外に結果に関わる情報を一切出さない。

## 2. 16 タイプの枠組み

### 2.1 4 つの軸

MBTI の 4 つの二分法（エネルギーの向き・ものの見方・判断のしかた・外の世界への接し方）にならい、
他人から見える言葉に言い換える。

| 軸            | 記号  | 左の極                       | 右の極                       | 他人から見える違い                                 |
| ------------- | ----- | ---------------------------- | ---------------------------- | -------------------------------------------------- |
| A1 エネルギー | E / I | **外向** E「ワイワイ充電」   | **内向** I「ひとり充電」     | 人と過ごして元気になるか、一人の時間で元気になるか |
| A2 ものの見方 | S / N | **現実** S「目の前のリアル」 | **直観** N「頭の中の可能性」 | 具体的な事実を話すか、想像・アイデアを話すか       |
| A3 判断       | T / F | **思考** T「ロジック優先」   | **感情** F「気持ち優先」     | 理屈と効率で決めるか、人の気持ちを大事に決めるか   |
| A4 接し方     | J / P | **計画** J「きっちり段取り」 | **柔軟** P「その場のノリ」   | 前もって決めて動くか、成り行きに合わせて動くか     |

### 2.2 4 つのグループ（「界隈」）

16 タイプを 4 つにまとめる。まとめ方は、MBTI 系の診断で一般的な「NT・NF・SJ・SP」の組み合わせに従う
（2 文字目が N のときは 3 文字目、S のときは 4 文字目で分ける）。
名前は、いまの若い世代に通じる「〜界隈」という言い方で付ける。

## 3. 質問

### 3.1 作り方の決まり

1. 質問は **32 問**（1 つの軸に 8 問）。そのうち、一人が答えるのは **16〜32 問**（§3.5）。だいたい 3 分で答え終わる量にする
2. 各軸 8 問は、**基本 4 問**（全員が答える）と**深掘り 4 問**（必要な人だけ）。どちらも**左の極向き 2 問・右の極向き 2 問**。「なんでも『そう思う』と答えてしまう癖」（黙従傾向）が結果を一方に寄せないようにするため
3. 友達が**見聞きできる行動**で書く（§0.4）。深掘りの問は、基本の問より具体的な場面で聞く
4. 主語は `{name}`（ホストが付けた呼び名）。「{name}は」で始めて自然に読めるようにする
5. 軸が続けて並ばないよう、A1→A2→A3→A4 を繰り返す順で出す。並び順は全員同じにする（順番による偏りを人によって変えないため）
6. 「〜しない」のような打ち消しの文は使わない（読み違いが増えるため）
7. 最初に選んだ関係（§3.6）に合わせて、その関係で見られる場面の言い方に差し替える。意味（どの極の行動か）は変えない

### 3.3 自己回答用の言い換え

同じ 32 問を、主語を「わたし」に、文末を自分のことに合う形に直したものを使う。場面の差し替えはしない（自分のことなので、ふだんの文で聞く）。
意味を変えないこと。例：

- Q1「わたしは、初対面の人がいても自分から話しかけにいく」
- Q2「わたしは、大人数で過ごしたあと、ひとりの時間がほしくなる」
- Q18「わたしは、相談されると、まず相手の気持ちに共感する」

32 問すべての自己回答版は、データファイル（§11.4 `src/data/questions.ts` の `selfText`）に持たせる。

### 3.4 答え方

- 7 段階：「ちがう」←●●●○●●●→「そう」。左から 1〜7 の値を持つ。真ん中（4）は「どちらとも」
- 加えて「**わからない**」を選べる（友達が見たことのない行動もあるため。例：部屋の様子）。自己回答では選べない
- 1 つの軸で、1〜7 で答えた問が 3 問未満だと、その軸を判定できない。送信の前にその軸の問へ戻るよう案内する（§5.3）

### 3.5 答えによって出す問を変える（深掘り）

1. まず基本の 16 問に答えてもらう
2. 基本の 16 問に答え終わったら、軸ごとに、基本の問だけで次を確かめる
   - 1〜7 で答えた基本の問が 3 問未満（「わからない」が多い）
   - または、1 問あたりの点（§6.1 の `s`）の平均が −1 より大きく +1 より小さい（＝合計の絶対値が答えた問の数より小さい。半々に近い）
3. どちらかに当たる軸だけ、その軸の深掘り 4 問を後ろに足す。足す順は §3.2 の深掘りの表の順
4. ハッキリした人は 16 問、全部の軸が半々に近い人は 32 問になる。足した問の数は画面で知らせる（§4.8）
5. 前の問に戻って基本の答えを変えたら、もう一度 2 を確かめ直す。出さなくなった深掘りの問の答えは送らない
6. サーバーでも同じ決まりで確かめ、出すべき深掘りの問が抜けている回答や、出していない問に答えている回答は受け付けない（§5.3）
7. 送る形：32 問ぶんの値を番号順に並べる。1〜7 は答え、0 は「わからない」、−1 は出していない問

理由：半々に近い軸ほど、問を増やすと結果が安定する。ハッキリした軸に同じ数の問を重ねても結果はほとんど変わらないので、答える人の手間を減らす。

## 4. 画面

すべてスマホの縦持ちを基準にする（幅 360〜430px）。パソコンでは中央に最大幅 480px の列で表示する。

### 4.1 画面一覧

| ID  | 画面                             | URL                                      | 見る人                               |
| --- | -------------------------------- | ---------------------------------------- | ------------------------------------ |
| S1  | トップ                           | `/`                                      | だれでも                             |
| S2  | 診断を作る                       | `/new`                                   | ホスト                               |
| S3  | 自己回答                         | `/h/self#{hostKey}`                      | ホスト                               |
| S4  | 招待リンクの共有                 | `/h/share#{hostKey}`                     | ホスト                               |

### 4.2 S1 トップ

- 大きな見出し：「友達が答える、あなたの 16 タイプ」
- 小見出し：「自分で答える診断とはちがう、"周りから見たあなた"がわかる」
- ボタン 1 つ：「診断をつくる（無料・登録なし）」
- 下に 3 枚の説明カード：①人数を決めてリンクを送る ②友達が 3 分で答える ③全員そろったら結果発表
- 4 つの界隈を色付きで紹介（タップで各界隈の 4 タイプを表示）
- この端末で作った診断があれば、「つくった診断」として一覧で出す（§8.3）

### 4.3 S2 診断を作る

1 画面に 2 項目だけ。入力が少ないほど作る人が増えるため。

1. **呼び名**（必須、1〜12 文字）
   - 見本：「たろう」「はなちゃん」
   - 質問文に「{name}は、…」と入るので、その見本を入力欄の下にリアルタイムで表示する
2. **何人に答えてもらう？**（必須、3〜30 人、初期値 5）
   - 「−」「＋」ボタンと大きな数字。長押しで連続して変わる
   - 下に「人数がそろうまで結果は見られません。確実に答えてくれる人数にしよう」と出す

ボタン：「つくる」。押すと診断ができ、S3 の案内へ進む。

**作ったあとは、人数をふやせるが、へらせない**（§5.4）。依頼の条件「指定した人数が答え終わってから結果を出す」を守るため、
減らして早く結果を見ることはできないようにする。作る前の確認ダイアログでこの点を伝える。

### 4.4 S3 自己回答（任意）

- 冒頭：「先に自分でも答えておくと、「自分が思う自分」と「周りから見た自分」のギャップがわかる」
- ボタン：「答える（約 3 分）」「あとで」「答えない」
- 質問の画面は R2 と同じ部品を使い、文だけ自己回答版にする。「わからない」は出さない（自分のことなので）
- 自己回答は**結果が確定するまで**いつでも出し直せる。確定した後は変えられない
  （結果を見てから答えると、結果に引きずられてギャップが正しく出ないため）

### 4.5 S4 招待リンクの共有

- 招待リンク（`/a/{surveyId}`）を大きく表示
- ボタン：「LINE で送る」（LINE の共有 URL）、「コピー」、「その他」（端末の共有機能 `navigator.share`）、「QR コード」
- 送る文の見本（コピーでいっしょに入る）：「わたしについて答えて！友達から見た 16 タイプがわかるらしい。3 分・匿名だよ → {URL}」
- 注意書き：**管理用のリンク**（`/h#{hostKey}`）は自分だけのもの。なくすと結果を見られないので、「自分に送っておく」ボタンで保存をすすめる

### 4.6 S5 回答状況

- 大きな表示：「3 / 5 人 回答ずみ」と、人数分の丸（答えた人の分だけ色が付く）
- 丸は答えた順に色が付くだけで、だれが答えたかは出さない
- そろうまで、**結果につながる情報は一切出さない**（途中の割合・傾向も出さない）
- あと何人かを言葉でも出す：「あと 2 人で結果発表！」
- ボタン：「もう一度リンクを送る」「自己回答をする／直す」
- 10 秒ごとに状況を取り直す（画面が見えているときだけ。§11.3）
- 人数がそろったら、画面全体で「そろった！」の演出 → 「結果を見る」ボタン

### 4.7 R1 回答のはじめ

- 「**{name}** について答えてください」
- 「約 3 分・16〜32 問・匿名。{name} にはだれが何と答えたかは見えません」
- 「答えによって、次の質問が変わります」「見たことのない行動は『わからない』を選べます」
- ボタン：「はじめる」→ 関係を選ぶ画面（§3.6）→ 質問
- 締め切り済み・期限切れなら E1 を出す

### 4.8 R2 質問（いちばん大事な画面）

**1 画面に 1 問**。考える量を減らし、指一本で進められるようにする。

```
┌────────────────────────┐
│ ←      7 / 16      ━━━━──── │  ← 戻る・番号・進み具合の帯
│                              │
│  たろうは、                   │
│  その場のノリで予定を          │  ← 質問文（大きめ・2〜3 行）
│  変えても平気だ                │
│                              │
│  ちがう ●  ●  ●  ○  ●  ●  ● そう │  ← 7 つの丸。両端ほど大きい
│                              │
│        わからない              │  ← 文字だけの控えめなボタン
└────────────────────────┘
```

- 丸の大きさ：両端 56px、内側に行くほど小さく、真ん中 36px。どれも押せる範囲は 44px 以上（§10.2）
- 色：左側は灰がかった色、右側は診断のテーマ色。真ん中は無色
- 丸を押すと、**0.25 秒後に自動で次の問へ**。軽く震わせ（対応端末のみ）、押した丸が一瞬ふくらむ
- 左右のスワイプでも前後の問へ動ける。戻ったときは前の答えが選ばれた状態で出る
- 番号の分母は、そのときに出すと決まっている問の数（最初は 16）。深掘りの問を足したときは分母が増え、「もう少しだけ！ あと 4 問」のように足した数を知らせる
- 基本の問の 4 問ごとに短いひとこと（例：「いいペース！」「あと半分！」「ラスト 4 問！」）を出す
- 途中で閉じても、同じ端末で開き直せば続きから（答えはその端末の中だけに保存。§8.3）

### 4.9 R2 の最後：確認と送信

- すべての問のあと、「これで全部です」の画面。「質問にもどる」で戻れる
- 判定できない軸があれば、その軸の「わからない」の問へ案内する（§3.4）
- 送信ボタン：「送る」
- 送信中は二度押しできないようにする

### 4.10 R3 回答完了

- 「ありがとう！ {name} の結果は、{N} 人そろったら {name} だけが見られます」
- あと何人で結果が出るかを表示：「あと 2 人」（人数だけ。中身は出さない）
- 誘導：「あなたも友達に答えてもらう？」→ S2
- 回答者に、そのホストの結果は見せない（ホストが公開した場合は S7 で見られる）

### 4.11 S6 結果発表

開くとまず演出（2〜3 秒、飛ばせる）：

1. 画面が暗くなり「{N} 人の答えを集計中…」
2. 4 つの軸の文字が 1 つずつ回転して止まる（E→N→F→P のように）
3. 界隈の色が広がり、4 文字とタイプ名が出る

続いて下に長く読める分析（中身は §7）。上から順に：

1. タイプのカード（4 文字・界隈・タイプ名・キャッチ・タグ）
2. 4 軸メーター
3. 友達から見たあなた（本文）
4. 強み／ちょっと気をつけたいところ
5. データでわかるあなた（回答の数字から作る文）
6. 自分 vs 周り（自己回答があるとき）
7. 関係ごとの見え方（条件を満たすとき）
8. 相性のいいタイプ（遊び）
9. シェア

折りたたみ：5〜8 は見出しを押すと開く形にして、最初の画面が長くなりすぎないようにする。

### 4.12 シェア

- 「画像で保存」：縦 1080×1920（ストーリー用）と横 1200×630 の 2 種
- 画像に入れるのは：呼び名・4 文字・界隈・タイプ名・キャッチ・4 軸の % ・回答人数・アプリ名
- 画像に**入れない**もの：関係ごとの内訳、自己回答（他人に見せる前提ではないため）
- 「リンクで公開」：S7 用の URL を作る。ホストが押したときだけ作り、いつでも取り消せる
- 「X に投稿」「LINE で送る」

## 5. 状態と決まり

### 5.1 診断の状態

```
            作る
             │
             ▼
   ┌──── 受付中 ────┐
   │   (open)      │  N 人目が答える
   │               ├────────────→ 確定 (completed)
   │               │←────────────┤ 人数をふやす（§5.4）
   │ 期限が来る     │                  │
   ▼               │                  │ ホストが消す / 保存期限
 期限切れ (expired) │                  ▼
   │               │               削除 (データを物理削除)
   └── ホストが消す ─┴───────────────→
```

| 状態     | 回答の受付 | 結果の表示 | 自己回答 |
| -------- | ---------- | ---------- | -------- |
| 受付中   | する       | しない     | できる   |
| 確定     | しない     | する       | できない |
| 期限切れ | しない     | しない     | できない |

### 5.2 期限

- 受付中の期限：作ってから **30 日**。S5 から 1 回だけ **30 日延長**できる（合計 60 日まで）
- 確定した診断の保存期限：確定から **180 日**。過ぎたら全データを消す。S6 で残り日数を出す
- 期限切れの診断：期限切れから **30 日** で全データを消す
- ホストはいつでも診断を消せる（確認ダイアログあり）。消したら元に戻せない

### 5.3 回答の受付の決まり

1. 受付中のときだけ受け付ける
2. 各軸で 3 問以上に 1〜7 の答えがあること。なければ受け付けない（画面でも先に止める）
3. **N 人目まで**しか受け付けない。同時に 2 人が最後の 1 枠に送ったときは、先にデータベースに入った 1 人だけを受け付け、もう 1 人には「ちょうど締め切られました。ありがとう！」と出す（§11.2 の方法で確実に守る）
4. 同じ端末からの 2 回目は受け付けない（§8.3）。ただし完全には防げない（§8.4）
5. N 人目を受け付けたのと**同じ処理の中で**、結果を計算して保存し、状態を「確定」にする

### 5.4 人数をふやす

ホストは、トップの「つくった診断」、回答状況（S5）、結果（S6）から「人数をふやす」画面へ進み、人数をふやせる。

- **同じ招待リンクのまま**受付を続ける。それまでの回答はそのまま使い、前に答えた人はもう一度は答えられない（§5.3 の 4）
- **受付中**：1 人以上ふやせる
- **確定**：**3 人以上**ふやす。受付中に戻し、新しい人数がそろったときに、全員の回答で結果を出し直す
  - 3 人以上にするのは、1〜2 人だけふやすと、前の結果と新しい結果の差から、あとから答えた人の答えの傾向が分かってしまうため（§8.5）
  - それまでの結果・公開リンク（S7）は消す。公開していた場合は、新しい結果が出てから作り直す
  - 受付の期限は、ふやした日から 30 日にし、延長（§5.2）をもう一度使えるようにする
- 上限は 30 人。期限切れの診断と、古い版の問（§6.8）で作った診断はふやせない
- 人数はへらせない
- 行の鍵をかけた 1 つの処理の中で確かめて書きかえる（N 人目の回答と同時に来ても、どちらか一方の順になる）
- ふやしたあとは、招待リンクの共有画面（S4）へ進む

## 6. 判定の計算

計算はすべてサーバーで、**整数だけ**を使って行う（小数の誤差で「ちょうど半々」の判定がずれないように）。

### 6.1 1 問の点

回答 `a`（1〜7）から `v = a − 4`（−3〜+3）を作る。
その問が**左の極向き**（E・S・T・J）なら `s = v`、**右の極向き**（I・N・F・P）なら `s = −v`。
つまり `s` が正なら左の極、負なら右の極に寄っている。「わからない」は計算に入れない。

### 6.2 1 人の軸の点

回答者 `r` の軸 `k` の点：

```
x(r,k) = (その軸で答えた問の s の合計) × 840 ÷ (その軸で答えた問の数)
```

答えた問の数は 3〜8（深掘りした軸は最大 8 問）で、840 は 1〜8 のどれでも割り切れるので、`x` は必ず整数になる（−2520〜+2520）。
840 を掛けて問の数で割るのは、答えた問の数がちがう人どうし（深掘りした人・しない人、「わからない」が多い人）を同じ重みで比べるため（1 人 1 票）。
「わからない」と、出していない問は計算に入れない。

### 6.3 全員の軸の点

```
X(k) = Σ_r x(r,k)          （N 人分の合計、整数）
平均 = X(k) ÷ N            （−2520〜+2520）
左の極の割合(%) = 50 + 平均 ÷ 2520 × 50   →  四捨五入で整数に（0〜100）
```

- `X(k) > 0` → 左の極（E・S・T・J）
- `X(k) < 0` → 右の極（I・N・F・P）
- `X(k) = 0` → §6.4

画面には**選ばれた極の割合**を出す（例：右の極なら `100 − 左の割合`）。四捨五入の結果がちょうど 50% でも、`X(k)` の符号で決めた極を出す。

### 6.4 ちょうど半々のとき（`X(k) = 0`）

次の順に決める。前の手順で決まれば、そこで止める。

1. `x(r,k) > 0` の人数と `x(r,k) < 0` の人数を比べ、多いほう
2. 自己回答があれば、その軸の自己の点の符号
3. 「強くそう思う」寄りの答え（`|s| = 3`）だけを足した合計の符号
4. それでも決まらなければ、右の極（I・N・F・P）にする（決まりを固定しておくため。理由は特にない）

いずれの場合も、その軸に「**ど真ん中**」の印を付け、分析文で必ず触れる（§7.5）。

### 6.5 一致の度合い

軸ごとに、N 人のうち選ばれた極と同じ向きの人（`x(r,k)` の符号が同じ人、0 の人は含めない）の割合 `c` を出す。

| 条件                         | 表示         |
| ---------------------------- | ------------ |
| 全員が同じ向き（`c = 100%`） | 満場一致     |
| `c ≥ 75%`                    | ほぼ一致     |
| `50% < c < 75%`              | 多数派       |
| `c ≤ 50%`                    | 意見が割れた |

（`c ≤ 50%` でも、極は `X(k)` の合計で決まる。少数の人が強く答えた場合に起こる。分析文で触れる。）

### 6.6 寄り具合の言葉

選ばれた極の割合 `p` から：

| `p`     | 言葉     |
| ------- | -------- |
| 50〜54  | ほぼ半々 |
| 55〜64  | やや     |
| 65〜79  | しっかり |
| 80〜100 | 振り切れ |

### 6.7 自己回答の点

自己回答も §6.1〜6.2 と同じ式で `x(self,k)` を出し、割合 `p_self` に直す。
自己回答は**全員の点 `X(k)` に入れない**（あくまで「周りから見た」結果にするため。ただし §6.4 の 2 で半々のときだけ使う）。

### 6.8 計算の版

計算の決まりを将来変えても、確定済みの結果は変えない。結果に `algorithmVersion` を保存する。

- 版 1：24 問・全員が全問に答える・目盛り 60
- 版 2（いま）：32 問から 16〜32 問を出す（§3.5）・目盛り 840。版 1 で確定した結果の分析の文（D5〜D7）は、版 1 の問の要約で出す
- 診断にも作ったときの問の版（`question_version`）を保存する。今の版でない問で作った受付中の診断は、答えを混ぜられないので期限切れとして扱う

### 6.9 計算例（テストにも使う）

N = 3、軸 A1 だけを例にとる（基本 Q1〜Q4・深掘り Q5〜Q8）。

| 回答者 | Q1(E) | Q2(I) | Q3(E)      | Q4(I) | Q5(E) | Q6(I) | Q7(E) | Q8(I) |
| ------ | ----- | ----- | ---------- | ----- | ----- | ----- | ----- | ----- |
| r1     | 7     | 2     | 6          | 3     | —     | —     | —     | —     |
| r2     | 5     | 4     | わからない | 3     | 5     | 3     | 4     | 5     |
| r3     | 3     | 5     | 4          | 6     | —     | —     | —     | —     |

（— は出していない問）

- r1：基本 s = (+3, +2, +2, +1) → 合計 8、4 問。|8| ≥ 4 なので深掘りしない → x = 8×840÷4 = **1680**
- r2：基本 s = (+1, 0, —, +1) → 合計 2、3 問。|2| < 3 なので深掘りする。深掘り s = (+1, +1, 0, −1) → 全部で合計 3、7 問 → x = 3×840÷7 = **360**
- r3：基本 s = (−1, −1, 0, −2) → 合計 −4、4 問。|−4| ≥ 4 なので深掘りしない → x = −4×840÷4 = **−840**
- X = 1680 + 360 − 840 = **1200** > 0 → **E**
- 平均 = 1200 ÷ 3 = 400 → E の割合 = 50 + 400÷2520×50 ≈ 57.94 → **58%**（やや外向）
- 一致：E 向きは r1・r2 の 2 人 → c = 67% → **多数派**

## 7. 分析文

### 7.1 方針

- 「正しい」：数字に裏付けのない言い切りをしない。データから言えることは数字を添えて言い、タイプの一般的な傾向は「〜と見られがち」「〜タイプ」と書く
- 「詳しい」：タイプの文（全員共通）に、その人の回答から作る文（その人だけ）を重ねる
- 「面白い」：友達あるある・具体的な場面・軽いツッコミで書く。ただし相手を傷つける言い方、外見・能力・性別・恋愛の決めつけはしない
- 長さの目安：全部開いて 1,500〜2,500 字

### 7.2 タイプのカード

§2.3 の、4 文字・界隈・タイプ名・キャッチ・タグを出す。
4 文字はタイプ名のすぐ上に、タイプ名と同じくらいの大きさで出す（いちばん目に入り、ほかの診断と見比べやすいように）。
4 つの軸のうち「ど真ん中」があれば、カードの 4 文字のその文字を半分ずつの色にし、小さく「どっちも」と添える。

### 7.3 4 軸メーター

軸ごとに 1 本の横長の帯。左右に極の名前、選ばれた側に割合、帯の下に「寄り具合の言葉」と「一致の度合い」。

```
外向 ━━━━━━━●━━━━ 内向
ワイワイ充電 61%（やや）・多数派
```

### 7.4 タイプの本文（§12 にタイプごとの文を持つ）

| 部品                       | 中身                                                      | 長さ         |
| -------------------------- | --------------------------------------------------------- | ------------ |
| 友達から見たあなた         | 周りからどう見られているか。具体的な場面を 2 つ以上入れる | 230〜350 字  |
| 強み                       | 3 つ。それぞれ見出し＋1 文                                | 各 25〜60 字 |
| ちょっと気をつけたいところ | 2 つ。責めずに、場面と小さなコツをセットで                | 各 40〜80 字 |
| 友達のあるある             | 友達が言いそうな一言を 3 つ（「」付き）                   | 各 5〜30 字  |
| 相性のいいタイプ           | 2 つ（§7.8）                                              | —            |

### 7.5 データでわかるあなた（回答から自動で作る文）

次の規則で、条件を満たすものを**上から最大 6 つ**まで出す。数字はすべて実際の回答から入れる。

| 規則                    | 条件                                                                                                                                                                              | 文の型（例）                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| D1 いちばん強い軸       | 寄り具合 `p` が最も大きい軸（同じなら A1→A4 の順で先）。その軸もど真ん中なら出さない                                                                                              | 「いちばんハッキリ出たのは **{極名}**（{p}%）。{N} 人から見て、ここはあなたの"看板"です」             |
| D2 満場一致             | 一致が「満場一致」の軸（複数あれば 1 つの文にまとめる）                                                                                                                           | 「**{極名}・{極名}** は {N} 人全員の意見が一致。だれの目にもそう映っています」                        |
| D3 ど真ん中             | §6.4 の印がある軸（複数あれば 1 つの文にまとめる）                                                                                                                                | 「**{左極名}** と **{右極名}** はちょうど半々。場面や相手によって使い分けているようです」             |
| D4 意見が割れた         | 一致が「意見が割れた」の軸のうち、ど真ん中でなく、D8 にも当たらないもの（複数あれば 1 つの文にまとめる）                                                                          | 「**{軸名}** は意見が割れました。見せている顔が、相手によってちがうのかも」                           |
| D5 みんなが認めた行動   | 1〜7 で答えた人のうち 5 以上を選んだ割合が最も高い問（3 分の 2 以上のときだけ。同じなら番号の若い問）                                                                             | 「{答えた人数} 人中 {人数} 人が『{質問の要約}』に"そう思う"。友達の目にもはっきり映っている行動です」 |
| D6 みんなが否定した行動 | 3 以下を選んだ割合が最も高い問（3 分の 2 以上のときだけ）                                                                                                                         | 「『{質問の要約}』は {人数} 人が"ちがう"。友達から見ると、あまりしない行動のようです」                |
| D7 謎の行動             | 「わからない」を選んだ人が最も多い問（半数以上のときだけ）                                                                                                                        | 「『{質問の要約}』は {人数} 人が"わからない"。ここはまだ友達に見せていない一面かも」                  |
| D8 少数の強い声         | 一致が「意見が割れた」で、ど真ん中でなく、選ばれた極の向きの人数が反対の向きの人数以下の軸（＝人数では勝っていないのに、強い答えの合計で決まった。複数あれば 1 つの文にまとめる） | 「人数では割れたけど、強く感じている人の声で決まりました：**{軸名}** は **{極名}**」                  |

- 同じ規則に当たる軸が複数あっても 1 つの文にまとめる。同じ言い回しの文が続いて 6 つの枠を埋め、D5〜D8 のような回答ならではの文が押し出されるのを防ぐため
- ど真ん中の軸は D3 で触れるので、D4 には入れない（全員がちょうど 0 の軸は一致の度合いが「意見が割れた」になるが、実際には割れていないため）
- 「質問の要約」は、質問ごとに用意した短い言い方を使う（例：Q1 →「初対面でも自分から話しかける」）。§11.4 `src/data/questions.ts` の `summary`
- 人数は「{答えた人数} 人中」と書き、「わからない」の人を分母に入れない
- D5〜D7 は、その問を出した人だけで数える。深掘りの問は一部の人にしか出ないので、**その問を出した人が 3 人以上**の問だけを使う（少ない人数だと、だれの答えか分かってしまうため）
- 割合の表し方：全員のときは「全員」と添える。それ以外は人数だけで書く

### 7.6 自分 vs 周り（自己回答があるときだけ）

軸ごとに、自己の割合と周りの割合を並べた図（上下 2 本の帯）を出し、次の文を付ける。

| 条件                                     | 文の型                                                                                                                   |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 極がちがう                               | 「自分では **{自己の極}** だと思っているけど、周りからは **{周りの極}** に見えています。意外な一面が外に出ているのかも」 |
| 極は同じで、差が 20 ポイント以上         | 「どちらも **{極}** だけど、周りのほうが {多い/少ない}。自分が思うより{強く/控えめに}出ています」                        |
| 自分の点がちょうど 0 で、周りが 70% 以上 | 「自分では **どちらとも言えない** と思っているけど、周りからはハッキリ **{周りの極}**（{p}%）に見えています」            |
| 差が 20 ポイント未満                     | 「自分の見方と周りの見方がほぼ一致。自分をよく分かっています」                                                           |

自分の点がちょうど 0 の軸は、§6.4 の手順 4 に合わせて右の極として扱う（自分で思うタイプの 4 文字に使う）が、「極がちがう」とは言わない（どちらとも答えていない人に「〜だと思っている」とは言えないため）。
4 軸すべてが「ほぼ一致」なら、まとめに「自己理解の達人」と出す。2 軸以上で極がちがえば「ギャップ萌えタイプ」と出す。
自己のタイプ（4 文字）も並べて出す：「自分で思うタイプ：{タイプ名}」。

### 7.7 関係ごとの見え方

X1 で同じ関係を選んだ人が **3 人以上いる関係が 2 つ以上**あるときだけ出す（少ない人数で出すと、だれが答えたか分かってしまうため）。
その関係の人だけで §6 と同じ計算をして、関係ごとのタイプ名を並べる。

> 例：「同じ学校の友達から見ると **お祭り番長**、職場・バイトの人から見ると **現場監督**。場所によってキャラを使い分けています」

### 7.8 相性のいいタイプ（遊び）

タイプごとに 2 つ決めておく（§12）。「一緒にいるとラク」「刺激をくれる」の 2 種類。
科学的な根拠はないので、見出しに「おまけ」と書き、「相性に正解はありません」と添える。

### 7.9 文の言い方の決まり

- 呼びかけは「あなた」。ホストの呼び名は質問文だけで使う
- 「〜です／〜ます」の丁寧な話し言葉を基本にし、尊敬語・謙譲語は使わない。「あるある」などのひとこと部分だけはくだけてよい
- 絵文字は使わない（環境で見た目が変わるため。代わりに自前の小さな絵を使う）
- 「〜すべき」「〜しなさい」は使わない

## 8. 匿名性・安全

### 8.1 集める情報

| 情報                                 | 集める             | 理由                                             |
| ------------------------------------ | ------------------ | ------------------------------------------------ |
| ホストの呼び名                       | する               | 質問文に入れるため。本名でなくてよいと画面に書く |
| 回答（16〜32 問・関係）              | する               | 判定のため                                       |
| メールアドレス・電話番号・アカウント | **しない**         | 不要。登録なしで使える方が気軽                   |
| IP アドレス                          | 保存しない         | 連続投稿の制限に一時的に使うだけ（§8.4）         |
| 端末の識別子                         | 診断ごとの乱数だけ | 二重回答の防止。端末をまたいだ追跡はしない       |

### 8.2 鍵の作り方

- `surveyId`（招待リンク）・`hostKey`（管理リンク）・`shareId`（公開リンク）は、それぞれ別に作った暗号的に安全な乱数（128 ビット以上、URL に使える文字で 22 文字程度）
- データベースには `hostKey` そのものではなく、その**ハッシュ値（SHA-256）**を保存する。データベースが漏れても管理画面に入れないようにするため
- 招待リンクから管理リンクを知る方法はない
- 管理用のリンクは `/h#{hostKey}` の形にし、API には `X-Host-Key` という見出し（ヘッダー）で渡す。URL のパスに入れないので、サーバーやホスティングの記録に残らない
- すべてのページで `Referrer-Policy: no-referrer` を返す

### 8.3 端末に保存するもの

| 保存先                                                     | 中身                          | 用途                                            |
| ---------------------------------------------------------- | ----------------------------- | ----------------------------------------------- |
| ホストの端末（ブラウザの保存領域）                         | 作った診断の `hostKey` の一覧 | S1 の「つくった診断」・ホスト自身の回答を止める |
| 回答者の端末                                               | 答えかけの回答                | 途中から続ける                                  |
| 回答者の端末＋サーバーが読む小さな記録（cookie、httpOnly） | 診断ごとの回答者の乱数        | 同じ端末の二重回答を止める                      |

ブラウザの保存領域は、内緒モードなどで使えないことがある。そのときも画面が壊れないようにし、
ホストには「管理リンクを自分に送っておいて」と強めに案内する。

### 8.4 防げないこと（正直に書いておく）

- 別の端末や内緒モードを使えば、同じ人が何度も答えられる。またホストが友達のふりをして答えることもできる。登録なしで気軽に使える代わりの割り切りとする
- 被害を小さくするため、同じ IP アドレスからの同じ診断への回答は **1 時間に 10 件まで**（学校や家庭の Wi-Fi で複数人が答える場合を考えて 1 件にはしない。これを超える人数が同じ回線から答えることはまれと見込む）。IP アドレスはハッシュ値にしてサーバーの記憶の中に 1 時間だけ持ち、保存しない。サーバーが複数台に分かれる環境では台ごとの数になるため、目安としての制限である
- 結果の注記で「回答は自己申告です」と書く

### 8.5 匿名性の決まり

- ホストには、だれが何と答えたかを**どの画面でも出さない**
- 1 人分の回答を推測できる表示をしない：人数の下限 3 人（§4.3）、関係ごとの表示は 3 人以上（§7.7）、結果が出たあとに人数をふやすときは 3 人以上（§5.4）、深掘りの問を使う分析の文は 3 人以上に出した問だけ（§7.5）。回答者が自由に文を書く欄は設けない（書きぶりで人が分かり、悪口の場にもなりうるため）
- 回答の時刻を画面に出さない（「さっき答えた人がこう答えた」と分かるため）。S5 の丸は、答えた数だけ色が付くことしか示さない

### 8.6 そのほかの安全

- 呼び名は表示のとき必ず文字として扱い、HTML として解釈しない（スクリプトの埋め込みを防ぐ）
- 呼び名に禁止語の一覧（悪口・差別語・性的な言葉など。`src/data/ng-words.ts`）を当て、当たれば作るときに止める
- 公開リンク（S7）は検索エンジンに載せない（`noindex`）
- 年齢：13 歳未満は保護者と使うよう利用規約に書く

## 11. 技術

### 11.1 構成

| 部分               | 選ぶもの                              | 理由                                                                 |
| ------------------ | ------------------------------------- | -------------------------------------------------------------------- |
| 画面とサーバー処理 | Next.js（App Router）＋ TypeScript    | 1 つの仕組みで画面と API が作れる。結果画像を作る仕組みもある        |
| データベース       | PostgreSQL（Neon・Supabase など）     | §5.3 の「N 人目まで」を、データベースの行の鍵で確実に守れる          |
| 置き場所           | Cloudflare Workers（OpenNext で変換） | 世界中の拠点で動き、無料の範囲が広い。定時処理（Cron Trigger）もある |
| 結果画像           | `next/og`（Satori）                   | サーバーで画像を作れる                                               |

Workers では通信の部品をリクエストをまたいで使い回せないので、データベースには問い合わせごとに接続する。接続を速くするため Cloudflare の Hyperdrive を通す（結果のキャッシュは切る。回答数・状態が古く見えないように）。Worker は Smart Placement でデータベースの近くに置く。
開発とテストでは、PostgreSQL がなくても動くよう PGlite（組み込みの PostgreSQL）を使う。

ブラウザから直接データベースに触らせない。読み書きはすべてサーバーの API を通す。

公開するアドレスは `https://takoshin.daigakunote.com`（Workers の独自ドメイン）。`workers.dev` のアドレスもそのまま使える。
転送（リダイレクト）はしない。端末に保存するもの（§8.3）はアドレスごとに分かれるため、転送すると、それまでのアドレスで作った診断の一覧が見えなくなるため。

### 11.2 データの形

```sql
-- 診断
create table surveys (
  id               text primary key,        -- surveyId（招待リンク）
  host_key_hash    text not null unique,    -- hostKey の SHA-256
  nickname         text not null,           -- 1〜12 文字
  target_count     smallint not null check (target_count between 3 and 30),
  response_count   smallint not null default 0,
  status           text not null default 'open'
                   check (status in ('open','completed','expired')),
  self_answers     smallint[] null,         -- 24 個。0 は「わからない」
  extended         boolean not null default false,
  expires_at       timestamptz not null,    -- 受付の期限
  completed_at     timestamptz null,
  delete_at        timestamptz null,        -- この時刻に物理削除
  result           jsonb null,              -- 確定した結果（§11.5）
  share_id         text null unique,        -- 公開リンク。公開していなければ null
  question_version smallint not null default 1,
  created_at       timestamptz not null default now()
);

-- 回答
create table responses (
  id             bigint generated always as identity primary key,
  survey_id      text not null references surveys(id) on delete cascade,
  respondent_key text not null,            -- 端末ごとの乱数
  answers        smallint[] not null,      -- 24 個。1〜7、0 は「わからない」
  relation       text null,
  created_at     timestamptz not null default now(),
  unique (survey_id, respondent_key)
);
```

**N 人目までを確実に守る方法**：回答の保存は 1 つのトランザクションで、

1. `select ... from surveys where id = $1 for update`（その診断の行を他の処理から一時的に止める）
2. 状態が `open` で、`response_count < target_count` かを確かめる。だめなら「締め切り」を返す
3. `responses` に追加し、`response_count` を 1 増やす
4. 増やした結果が `target_count` と等しければ、そのトランザクションの中で §6・§7 の結果を計算して `result` に入れ、`status = 'completed'`・`completed_at`・`delete_at` を入れる
5. 確定する

これで、同時に何人送っても N 人を超えず、結果は N 人分のデータだけで 1 回計算される。

期限切れ・削除は 1 日 1 回の定時処理（Cloudflare の Cron Trigger）で行う（`expires_at` を過ぎた `open` を `expired` に、`delete_at` を過ぎたものを削除）。

## 12. 16 タイプの本文

各タイプ：**友達から見たあなた**／**強み**（3）／**ちょっと気をつけたいところ**（2）／**友達のあるある**（3）／**相性**（ラク・刺激）。
この章は `src/data/types.json` と同じ内容である（食い違ったら `types.json` を正とする）。公開前に、全文を §7.9 の決まりで見直す。

### 考察界隈

#### INTJ 軍師

- **友達から見たあなた**：口数は多くないのに、話すと核心を突いてくる人。グループで何かを決めるとき、みんながまだ迷っているうちに「こうすればいいんじゃない？」と筋の通った案を出してくれます。旅行の計画で電車が止まっても、「じゃあこっちのルートで」と涼しい顔で代わりの道を出せるのは、頭の中で何通りも先を読んでいるから。ムダな集まりや中身のない会話は少し苦手そうで、そこがクールに見える理由かもしれません。でも一度信頼した相手には、驚くほど親身に知恵を貸してくれます。困ったときに「あの人に聞けば何とかなる」と思われている、頼れる作戦参謀です。
- **強み**：先を読む力（問題が起きる前に気づいて、静かに手を打っておけます。）／ブレない判断（周りの空気に流されず、筋の通ったほうを選べます。）／一人で深める集中力（調べ物や作戦づくりになると、だれよりも粘り強く本領を発揮します。）
- **気をつけたいところ**：正しさを優先して、言い方がそっけなく聞こえることがあります。結論の前に「いいね」を一言足すだけで、伝わり方が変わります。／計画が崩れると、顔に出さなくても内心かなり疲れるタイプ。予定の中に「何もしない時間」も入れておくとラクです。
- **あるある**：「もう答え出てるでしょ」／「そのやり方、非効率じゃない？」／「（実はめっちゃ調べてきてる）」
- **相性**：ラク＝ENTP、刺激＝ENFP

#### INTP 博士

- **友達から見たあなた**：気になることがあると、とことん調べないと気が済まない人。ふとした会話から急に「それってそもそも何で？」と深掘りが始まり、気づけば誰も知らない豆知識が出てきます。アニメや映画を見たあとに一番長い考察を語りだすのも、たいていこの人。好きなものの話になると止まらないのに、興味のない話題ではスッと静かになる分かりやすさも魅力です。人の意見にも「なるほど、でも…」と別の角度を出してくるので、議論すると面白い相手。ちょっと浮世離れして見えても、話を聞くと「そう考えるのか」と毎回驚かされる、頭の中が広い人です。
- **強み**：深掘り力（仕組みが分かるまで考え抜き、だれも気づかない答えにたどり着けます。）／柔らかい頭（前例やふつうにとらわれず、新しい見方を出せます。）／公平な見方（好き嫌いではなく筋で判断するので、相談相手として信頼されます。）
- **気をつけたいところ**：考えているうちに返事や行動が遅れて、「興味ないのかな」と思われることがあります。「考え中」と一言返すだけで安心してもらえます。／面倒な手続きや連絡を後回しにしがち。期限だけはカレンダーに入れておくと、あとで慌てずにすみます。
- **あるある**：「ちょっと待って、それ定義による」／「（3 時間前の話をまだ考えてる）」／「詳しすぎて逆に怖い」
- **相性**：ラク＝ENTJ、刺激＝ENFJ

#### ENTJ ボス

- **友達から見たあなた**：グループに一人いると、話がどんどん前に進む人。「じゃあ日程はこの日、場所はここで」と決めるのが速く、気づけば自然とまとめ役になっています。文化祭やイベントでは、だれに何を頼むかをさっと決めて、締め切りまでの道のりを引いてくれるタイプ。目標があると燃えるので、遊びのボウリングでも本気です。はっきり物を言うので最初は少し怖がられることもありますが、責任感が強く、困ったときに一番頼りになるのもこの人。「ついていけば何とかなる」という安心感を、周りに配っている存在です。
- **強み**：決める力（迷って止まっている場を、ひと言で前に進められます。）／やり切る力（目標までの計画を立て、最後まで走り切ります。）／人を動かす力（それぞれの得意を見抜いて、役割をうまく割り振れます。）
- **気をつけたいところ**：自分のペースで進めるあまり、置いていかれる人が出ることがあります。決める前に「みんなはどう？」と一度聞くと、ついてきてくれる人が増えます。／休むのが下手なタイプ。予定を詰めすぎていないか、ときどき見直して、何も決めない日を作ってみてください。
- **あるある**：「で、結論は？」／「幹事？いいよ、やる」／「（もう予約してある）」
- **相性**：ラク＝INTP、刺激＝INFP

#### ENTP 発明家

## 15. 出来上がりの条件

6. 自己回答があれば、ギャップが §7.6 のとおりに出る
7. 結果を画像で保存・シェアできる
8. §14 のテストがすべて通る
9. §13 の確認がすべて終わっている
